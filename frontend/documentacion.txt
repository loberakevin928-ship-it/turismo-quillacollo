🚀 GUÍA DE INICIO RÁPIDA (PASO A PASO)
1️⃣ Requisitos previos
Asegúrate de tener instalado:

Node.js (v18 o superior) → Descargar

MySQL (usamos XAMPP) → Descargar XAMPP

Git (opcional, para clonar) → Descargar Git

2️⃣ Clonar el repositorio (si no lo tienes localmente)
bash
git clone https://github.com/loberakevin928-ship-it/turismo-quillacollo.git
cd turismo-quillacollo
3️⃣ Configurar la base de datos
Abrir XAMPP y activar MySQL (y Apache si quieres phpMyAdmin).

Abrir phpMyAdmin (http://localhost/phpmyadmin) y crear una base de datos llamada:

text
turismo_quillacollo
con cotejamiento utf8mb4_unicode_ci.

Importar el script SQL que está en backend/db-init.sql (si no existe, usa el script completo que te di). Puedes copiar y pegar el contenido en la pestaña SQL de phpMyAdmin y ejecutarlo.

Si no tienes ese archivo, ejecuta el script completo que incluye todas las tablas (users, places, categories, services, events, important_dates, settings, etc.) y los datos de ejemplo.

4️⃣ Configurar variables de entorno (Backend)
Dentro de la carpeta backend/, crea un archivo .env con este contenido:

env
PORT=5000
DB_HOST=localhost
DB_USER=root
DB_PASSWORD=
DB_NAME=turismo_quillacollo
JWT_SECRET=clave_super_secreta_cambiar_en_produccion
JWT_EXPIRES_IN=7d
Nota: En XAMPP, DB_PASSWORD queda vacío (sin contraseña). Si tienes contraseña, colócala.

5️⃣ Instalar dependencias
Backend
bash
cd backend
npm install
Frontend
bash
cd ../frontend
npm install

📚 DOCUMENTACIÓN COMPLETA DEL SISTEMA
1. Objetivo del proyecto
Desarrollar un sistema web integral para la promoción turística, cultural y religiosa del municipio de Quillacollo (Cochabamba, Bolivia), que centralice información, permita la georreferenciación interactiva de atractivos y facilite la gestión de contenidos por parte del personal municipal.

2. Tecnologías utilizadas
Capa	Tecnologías
Frontend	React 18, Vite, Tailwind CSS v3, Leaflet (mapas), React Router v6, Axios, React Hot Toast, Lucide React, Recharts
Backend	Node.js, Express, MySQL (con mysql2/promise), JWT, Bcryptjs, Multer (subida de archivos)
Base de datos	MySQL (XAMPP / MariaDB)
Control de versiones	Git + GitHub
Entorno	Node.js v18+, npm

5. Roles y permisos
Admin: Acceso total al panel, puede crear/editar/eliminar cualquier recurso, registrar nuevos usuarios.

Editor: Puede gestionar lugares, eventos, servicios y galería, pero no usuarios ni configuración.

User: Solo puede ver contenido público y dejar reseñas (si se implementa).

6. Manual de usuario básico
Cliente / Visitante
Inicio: Mapa con todos los lugares turísticos. Panel lateral con filtros (búsqueda por nombre, categorías, distancia).

Detalle de lugar: Al hacer clic en un marcador o en una tarjeta, se muestra información completa (descripción, horario, dirección, galería, reseñas, mini mapa).

Servicios: Directorio de servicios (hoteles, restaurantes, artesanos, guías, transporte) con filtros y mapa de ubicación.

Calendario: Lista de fechas importantes (feriados, festividades, eventos) con filtros por categoría.

Administrador
Login: Accede con credenciales.

Dashboard: Resumen con tarjetas de estadísticas (total de sitios, eventos, usuarios, imágenes) y gráfico de visitas mensuales.

Sitios Turísticos: CRUD completo (crear, editar, eliminar). Cada sitio debe tener latitud, longitud y categoría.

Eventos: CRUD de eventos con fecha, ubicación y opción de destacado.

Servicios: CRUD de servicios, cada uno puede asociarse a un lugar turístico (para georreferenciación).

Usuarios: Lista de usuarios registrados, posibilidad de crear nuevos usuarios (solo admin).

Galería: Gestión de imágenes asociadas a los lugares.

Configuración: Edición de datos institucionales (nombre, teléfono, correo, redes sociales).

Reportes: Visualización de estadísticas avanzadas (próximamente con exportación a PDF/Excel).

7. Personalización y marca
Logo: Se puede subir desde el panel de administración (Configuración).

Colores: Definidos en frontend/tailwind.config.js y en frontend/src/index.css como variables CSS.

Tipografía: Google Fonts (Poppins).

8. Seguridad
JWT: Todas las rutas del panel de administración están protegidas con middleware authenticate.

Autorización: Middleware authorize para restringir según roles (admin o editor).

Contraseñas: Hasheadas con bcryptjs.

Variables de entorno: JWT_SECRET y credenciales de DB en .env.
